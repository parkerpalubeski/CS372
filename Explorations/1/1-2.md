## When a router sees an IP address, how does it know where to forward it?

The router consults a routing table to determine the route of a destination, which includes routers as midpoints. Because of this, I would speculate it might even use some kind of graphing algorithm to determine the shortest path between source and destination, where "nodes" are different routers and "cables" are the edges.

## If an IPv4 address is 4 bytes, roughly how many different computers can that represent in total, assuming each computer has a unique IP address?

Each byte is 2^8 bits, so: \
$2^8 = 256$ \
With 4 bytes: \
$256^4 = 4294967296$ \
So there are <ins>4294967296</ins> unique IPv4 addresses 

## Same question, except for IPv6 and its 16-byte addresses?

$256^{16} = ~3.4*10^{38}$ \

There are approximately <ins>3.4 * 10<sup>38</sup></ins> addresses in IPv6

## Speculate on why the IP header wraps up the TCP header in the layered model, and not the other way around.

I would assume that IP headers are wrapped last because it is decoded/re-encoded every time it hops to a new router, whereas TCP would be untouched. This might have a few advantages like the ability for packets to redirect if something is down or clogged.

## If UDP is unreliable and TCP is reliable, speculate on why one might ever use UDP.

TCP has checks that ensure that data isn't corrupted which I assume is the reason it is considered reliable. There was no mention of UDP having these checks, so my assumption is that these checks aren't there and any corrupted data is simply discarded. I believe UDP would thus be used for applications where speed is essential, downtime is problematic and lost data is less of an issue than lost speed. Without waiting for correct packets, UDP offers the best responsiveness and speed which would be essential for things like video streaming (e.g. a zoom call).
