## Using only the .to_bytes() and .from_bytes() methods, how can you swap the byte order in a 2-byte number? (That is reverse the bytes.) How can you do that without using any loops or other methods? (Hint: "big" and "little"!)

You can convert the number to bytes in on endianness (little or big) and then parse it back using the other endianness. Either way (little-to-big or big-to-little) works. If you already know the byte order, you can also just do it in one step.

## Describe in your own words the difference between Big-Endian and Little-Endian.

The difference is in the order of bytes. Little endian is by LSB first, and big-endian is by MSB first.

## What is Network Byte Order?

Network bytes are tranmitted as big-endian.

## Why not just send an entire number at once instead of breaking it into bytes?

Because bytes are how computers read large numbers. Also, especially in packet networks, an especially large number might not fit into one packet. So packing one (or an arbitrary number of) byte(s) each into packets helps break it up so it can actually be sent.

## Little-endian just seems backwards. Why does it even exist? Do a little Internet searching to answer this question.

Little-endian's purpose appears to be to speed up type conversion. For instance, a 64-bit integer 11011101 00000000 ... converts a lot faster than the same integer in big endian, ... 00000000 11011101, because the significant byte is right at the start.

## Describe the advantages from a programming perspective to abstracting packets out of a stream of data.

Separation of concerns is a big one. Being able to separate I/O and parsing is a major win for security, modularity, and testing.
